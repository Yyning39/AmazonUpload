# Amazon 跨站图片上传 项目说明

本程序跑在操作员的 Windows 本机上。CL 完成欧洲五国跟卖上架之后，由本程序在已登录的 Chrome 里上传站点图，并提交 A+。

下文分三部分：需求从哪来、程序按什么设计工作、当场怎么看一遍。任务字段、错误码和回写语句以 [Amazon跨站图片上传-设计文档.md](./Amazon跨站图片上传-设计文档.md) 为准。后台点击顺序以[亚马逊后台上传站点图片+提交应用 A+](https://aosom.feishu.cn/wiki/KXnEwlzFgijD4pkhpHacUG0GnTh)为准。

---

## 1. 需求背景

欧洲五国（英国、德国、法国、意大利、西班牙）的跟卖上架在 CL 里完成，逻辑与北美同一套。帖子变为 **Listed(A+已上传)**，或正常图片、AI 打标图片发生更新时，卖家后台还要补两步：

1. 把这次要上的图片传到该国 Seller Central 的图片管理页。
2. 若该商品已有类型为 EBC、状态为草稿的 A+，确认已应用的 ASIN 后提交批准。没有这类草稿则跳过，整单仍可成功。

这两步必须发生在本机已经登录的 Chrome 里。CL 服务器访问不到 `127.0.0.1`，也过不了卖家后台的登录和验证码。因此上传和提交放在本机程序：CL 写入一行任务，本机领取并操作页面，再把终态写回同一行。上架页按这一行展示结果。本程序不创建 Listing。

国家能力覆盖七国，另含美国、加拿大。CL 现阶段主要投欧洲五国。本期登录由人工在各国独立 Chrome 里保持。

## 2. 设计说明

### 2.1 分工

| 侧 | 负责 |
|---|---|
| CL | 跟卖上架；在「上架完成」「图片更新」两个时机插入任务行；按终态展示结果 |
| 本程序 | 轮询领取、下载图片、按跨站国别上传、提交 A+、本机重试、写日志、终态写回；登录失效时暂停该国并飞书告警 |

两种触发的步骤相同：先传站点图，再做 A+。站点图失败则不再做 A+。A+ 不依赖本次图片已经通过亚马逊审核。审核是后台异步结果，程序等到上传成功标志即可，不等待前台「已显示」。

### 2.2 一条任务怎么结束

正式通道是 CL 库 **cadev** 的表 `ca_pid_amz_cross_site_task_all`。公开连接项在 `config/settings.json` 的 `cl_db`（表名、库名、轮询间隔 30 秒、僵尸回收 1800 秒）。host、用户名、密码和飞书 webhook 只放 `config/settings.local.json`，不进仓库，也不打进发行包。

```text
CL 插入一行，TASK_STATUS = New，IMAGES、ACTIONS 等已填好
  → 本机轮询。仅当该行仍为 New 时改为 Process，并刷新 UPDATED_DATE
  → 空字段、非法 URL、国别无法识别等，直接 Error，不重试
  → 复制到本机 SQLite，按 CROSS_COUNTRY 连接该国 Chrome
  → 按 IMAGES 下载完整 URL，逐位上传
  → 有 EBC 草稿则提交；没有则跳过 A+
  → 站点图成功，且 A+ 成功或已跳过 → Confirm，清空错误信息
  → 可重试的失败：CL 保持 Process，本机记待重试
  → 不可重试，或已满 3 次 → Error，写入 ERROR_CODE、ERROR_MESSAGE
```

国别只认 `MAIN_COUNTRY` 和 `CROSS_COUNTRY`（`US` `CA` `UK` `DE` `FR` `IT` `ES`）。连接哪一个 Chrome、打开哪一国后台，以 `CROSS_COUNTRY` 为准。搜索词有 SKU 用 SKU，否则用 ASIN。缺 ASIN 时在入队时拦截，因为 A+ 要比对已应用 ASIN。

`IMAGES` 是 JSON 数组，每一项都是完整的 `http(s)` 地址。下标 0 对应 MAIN，1 到 7 对应 PT01 到 PT07，8 起对应 PT08、PT09，上一位成功后再等新格子出现。不上传 FRONT、SIDE、BACK。已有图按该位覆盖，不点「全部替换」。

同一 `TASK_ID` 再次执行时，已成功的站点图跳过，只重跑还没成功的步骤。超过 30 分钟没有心跳的 `Process` 回收为 `New`，避免进程退出后任务一直占着。

业务失败只写回任务行。飞书只在登录墙、密码被拒、验证码或拼图需要人工时发送。此时暂停该国全部任务，每 30 分钟再看是否已回到卖家后台，恢复后继续。登录问题不占用 3 次重试。

### 2.3 本机怎么操作浏览器

每个国家一个 Chrome 用户目录、一个调试端口，地址只绑定 `127.0.0.1`。Chrome 和本程序在同一台机器。程序通过 Chrome 自带的调试通道下命令，上传时把本机文件路径直接交给页面上的文件框。

Chrome 启动参数里有 `--remote-debugging-port`。这个端口是 Chrome 给开发者工具留的入口，上面的协议叫 Chrome DevTools Protocol（CDP）。本机先访问 `http://127.0.0.1:<端口>/json/list`，拿到当前标签页，再连接该页的 `webSocketDebuggerUrl`。连上之后，命令是一条条 JSON。`Page.enable`、`Runtime.enable`、`DOM.enable` 打开对应能力。搜索、滚动、点页面上的按钮、读某一格有没有图，都走 `Runtime.evaluate`：把一段页面脚本交给 Chrome，在这个标签页里执行，再把结果拿回来。调试地址只接受本机的 `127.0.0.1` 和 `localhost`。

图片格里有一个 `<input type="file">`。卖家后台的上传按钮被点下去时，页面会给这个文件框装上 `onchange`，并调用文件框自己的 `click()`，Windows 随之弹出「打开文件」窗口。本程序仍要点这个按钮，否则页面的上传处理装不上。点的那一瞬间把 `HTMLInputElement.prototype.click` 换成空函数，系统窗口不会出现，点完立刻换回原来的 `click`。

文件本身用 CDP 命令 `DOM.setFileInputFiles` 交给文件框，分三步：

1. `Runtime.evaluate` 在页面里找到这一格唯一的文件框，拿到浏览器里的节点对象。
2. `DOM.requestNode` 把这个对象换成 CDP 的 `nodeId`。
3. `DOM.setFileInputFiles` 把本机绝对路径写入该节点的文件列表。Chrome 自己读取这个路径上的文件。页面对此的反应，与操作员在对话框里选中同一文件相同，先前装上的 `onchange` 会接着执行。

路径写进文件框只表示文件已经交出。这一格出现临时图（`newly-uploaded-image`）或亚马逊图片地址（`url-image`），这一位才算上传成功。

| 国家 | 端口 | 首页 |
|---|---|---|
| 美国 US | 9222 | https://sellercentral.amazon.com |
| 加拿大 CA | 9223 | https://sellercentral.amazon.ca |
| 英国 UK | 9224 | https://sellercentral.amazon.co.uk |
| 德国 DE | 9225 | https://sellercentral.amazon.de |
| 法国 FR | 9226 | https://sellercentral.amazon.fr |
| 意大利 IT | 9227 | https://sellercentral.amazon.it |
| 西班牙 ES | 9228 | https://sellercentral.amazon.es |

图片管理页路径是 `/imaging/manage`，A+ 页路径是 `/enhanced-content/content-manager`。`country` 决定打开哪一国的 Chrome；`market`（正式任务里的 `CROSS_COUNTRY`）决定切到哪个站点、图片落在哪个国家模块。

传图时：打开图片管理页，搜索关键词，结果必须恰好 1 个商品，且该行 SKU 或 ASIN 与关键词一致，再滚到该国模块逐位上传。文件路径进入文件框不算成功，要看到临时图或亚马逊图片地址。

提交 A+ 时：用同一关键词搜索，在结果里找类型 EBC、状态草稿。0 条则跳过。多条取列表从上到下第一条。进入后核对已应用 ASIN 等于任务 ASIN，再经「下一步: 应用 ASIN」「下一步: 查看并提交」「提交以供批准」，直到状态为已提交。

允许的扩展名：`.gif` `.pjp` `.jfif` `.jpe` `.pjpeg` `.jpeg` `.jpg` `.png`。

### 2.4 代码怎么拆

仓库按目录分工：

| 目录 | 职责 |
|---|---|
| `app/` | 窗口、连接 Chrome、传图、提交 A+、本机队列 |
| `config/` | 公开运行参数。账号密码放 `settings.local.json`，不进仓库 |
| `docs/` | 项目说明、任务字段和错误码 |
| `samples/` | 演示用 Excel |
| `data/` | 本机任务队列 `queue.sqlite3`，运行后生成 |
| `logs/` | 运行日志 |
| `build/`、`dist/` | 打包中间文件，以及发给操作员的 exe |

运行时还有两处目录不在仓库里。图片落在 `D:\aosom\data\picture\<国家代码>\<sku>\<站点代码>\`。各国 Chrome 用户目录在 `%LOCALAPPDATA%\AosomImageAplus\chrome-profiles\<国家代码>\`，登录状态留在这里，和日常使用的 Chrome 分开。

源码文件再按步骤拆开：

| 文件 | 职责 |
|---|---|
| `main.py` | 打开账号与上传记录窗口 |
| `app/hub_ui.py` | 五国账号、选择 Excel、进度、上传记录 |
| `app/cdp.py` | 连接调试端口、发送命令 |
| `app/browser.py` | 按国家启动 Chrome、切站点、打开图片页和描述页 |
| `app/imaging_upload.py` | 搜索、定位国家模块、逐位交文件 |
| `app/aplus_upload.py` | 搜索 EBC 草稿、进入详情、提交批准 |
| `app/picture_save.py` | 按地址把图片存到本地目录 |
| `app/excel_io.py`、`app/queue_store.py` | 读表、本机 SQLite |
| `app/pipeline.py` | 按行串联连接、切站点、传图、A+ |

队列不操作浏览器。图片页和 A+ 页分开写。选择 Excel 是联调入口；自动触发以 CL 任务表为准。

## 3. 演示

当场演示走窗口里的 Excel 入口。准备一台已安装 Chrome 的 Windows，`D:\aosom\data\picture` 可写。库账号不是这次演示的前置条件。

### 3.1 启动

开发目录执行 `python main.py`。发给操作员时，双击 `更新版本.cmd` 打包，再双击 `dist\AosomImageAplus\AosomImageAplus.exe`，`_internal` 留在 exe 旁边。打包步骤见 [打包与运行.md](../打包与运行.md)。

窗口左侧是「账号管理」「上传记录」「选择 Excel」，下方是进度。

### 3.2 先登录五个国家

停在 **账号管理**，点「五个国家全部启动」。每个国家是独立窗口、独立用户目录。端口已经在听时，不会再开第二个窗口。

在对应 Chrome 里登录该国卖家后台，回到程序点「重新检查登录」。已登录的一行会显示已进入卖家后台（能看到账户切换条）。演示前英国、德国、法国、意大利、西班牙都应是已登录。

### 3.3 准备一行数据

表头与 `samples/示例导入.xlsx` 相同：

| 列 | 填写 |
|---|---|
| `sku` | 该国后台能搜到的货号，例如 `845-530V00GY` |
| `asin` | 该商品 ASIN。提交 A+ 时必填 |
| `country` | 打开哪一国 Chrome，例如 `ES` |
| `market` | 切到哪个站点，演示时与 `country` 相同，例如 `ES` |
| `picture` | `1` 表示传图 |
| `A+introduction` | `1` 表示提交 A+，`0` 表示这一侧不做 |
| `src` | 传图时必填。完整 `https://` 图片地址，多张用换行、分号或竖线分开，也认 JSON 数组 |

示例表里的地址是 `https://example.invalid/01.jpg`，只能用来看列。当场演示要换成能下载的真实图片，SKU、ASIN 换成该国后台真实存在的商品。搜索结果必须恰好 1 条。要演示 A+ 时，描述列表里要有一条名称与 SKU 相同、类型为 EBC、状态为草稿的记录。

图片会存到 `D:\aosom\data\picture\<国家代码>\<sku>\<站点代码>\`，文件名按顺序变成 `01`、`02`、`03`。`01` 对应国家模块第一个框，缺号不前移。

### 3.4 跑这一行

点「选择 Excel」，选中这张表。左侧进度按行显示：读取、连接 Chrome、切换站点、上传图片、提交 A+。当前这张表跑完之前不能再选下一张。

页面上的顺序是：

1. 连接 `country` 的调试端口，把账户切到 `market`。
2. `picture` 为真时，按 `src` 下载或复制图片，打开 `/imaging/manage` 并搜索。该格已有图时，先点这一格的删除并确认，再把新文件交给文件框。文件夹里没有的序号不改页面上的原图。
3. `A+introduction` 为真时，打开描述页，用 ASIN 和 SKU 搜索，点进第一条名称与 SKU 相同、类型 EBC、状态为草稿的描述，提交到状态为「已提交」。
4. 要求做的部分都成功，这一行状态为完成。两列都为假则跳过。图片这一侧失败时，描述页仍会继续。

### 3.5 对照结果

跑完后窗口切到 **上传记录**。

- **图片上传**：同一 sku 的一次上传合成一组，每张图单独一行，能看到页面位置、成功或失败、原因。
- **A+描述**：每行一条，能看到成功或失败原因。

可用站点、时间和关键词过滤，勾选后点「下载勾选」导出。明细同时写在项目目录的 `picture_log.md` 和 `aplus_log.md`，队列在 `data/queue.sqlite3`。

再到该国卖家后台核对：图片管理里对应格子出现新图或待审核标记；若本行做了 A+，那条草稿的状态应为已提交。
